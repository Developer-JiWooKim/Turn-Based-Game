# 최종 시스템 기획서 — Endless Expedition : Battle System

| 항목 | 내용 |
| :--- | :--- |
| 게임 가제 | Endless Expedition |
| 장르 | 턴제 JRPG 커맨드 배틀 + 로그라이크 무한 타워 |
| 선택한 시스템 | **전투 시스템 (Battle System)** — 조우 진입부터 보상 선택 반영까지 |

---

## 0. 문서 범위

### 0-1. 이 문서가 다루는 것

조우(스테이지) 1회의 시작부터 보상 반영·다음 스테이지 진입까지의 규칙 전체입니다. 구체적으로 **턴 순서 결정 / 타겟팅 / 데미지 계산 / 상태이상 / 스테이지 스케일링 / 로그라이크 보상 선택 / 세이브 체크포인트**를 포함합니다.

### 0-2. 이 문서가 다루지 않는 것

| 항목 | 이유 |
| :--- | :--- |
| Run Setup System (타이틀·캐릭터 선택·성향 배분) | 별도 시스템. `SystemFlowDiagram.md` 참조. 이 문서에서는 **입력 조건**으로만 다룸 |
| 장비 / 아이템 / 경험치 | 의도적 배제. 핵심 메카닉 2종의 직관성을 위해 제외 (`CoreMechanics.md` 7항) |
| 캐릭터 고유 액티브 스킬 | 미구현. 12장 위험 항목에 기재 |
| 연출·사운드·UI 비주얼 | 시스템 규칙이 아님 |

### 0-3. 용어 정의

| 용어 | 정의 |
| :--- | :--- |
| **Run** | 새 원정 시작부터 전멸(또는 중단)까지의 1회 플레이 |
| **Stage** | 조우 1회. 1부터 무한히 증가 |
| **Turn** | 생존 유닛 전원이 1회씩 행동하는 단위 |
| **Action** | 유닛 1명의 1회 행동 |
| **기준 스탯 (BaseStats)** | 캐릭터/몬스터 데이터 테이블에 적힌 원본 수치 |
| **자동 성장** | 스테이지 진급마다 기준 스탯 대비 자동으로 붙는 flat 증가분 |
| **선택지 성장 (ChoiceGrowth)** | 로그라이크 보상으로만 얻은 누적 증가분. 별도 집계 |
| **유효 스탯 (Effective)** | 상태이상 감소가 반영된, 계산에 실제로 쓰이는 값 |
| **어그로 가중치** | 몬스터가 단일 대상을 고를 때 쓰는 추첨 가중치 |

## 1. 시스템 이름

**Battle System** (전투 시스템)

---

## 2. 시스템 목적

> **한 문장:** 아이템과 경험치 없이, **"이번 턴에 누구를 때릴까"**와 **"이번 보상으로 무엇을 고를까"** 두 판단만으로 무한히 어려워지는 스테이지를 얼마나 오래 버티는지를 겨루게 한다.

### 2-1. 세부 목적

| # | 목적 | 이 목적을 담당하는 규칙 |
| :--- | :--- | :--- |
| 1 | 매 턴 의사결정을 발생시킨다 | 턴 순서 정렬(F-12) + 어그로 가중 추첨(F-11) — 적의 행동 순서와 위협도를 보고 점사 대상을 정하게 함 |
| 2 | 언젠가는 반드시 지게 만든다 | 몬스터 지수 성장 vs 플레이어 선형 성장(F-2 / F-3) |
| 3 | 그 패배를 늦추는 수단을 플레이어 손에 쥐여준다 | 로그라이크 선택지 9종(T5) + 파티 시너지(F-6) |
| 4 | 매 판 다른 전개를 만든다 | 가중치 추첨(F-10) + 랜덤 웨이브 풀(T7) |
| 5 | 런을 넘어선 성장을 남긴다 | 영구 포인트로 선택지 등장 확률 조절(F-9 / F-14) |

### 2-2. 성공 / 실패 조건

| 구분 | 조건 |
| :--- | :--- |
| **플레이어 승리 (스테이지)** | 적 유닛 전원의 HP가 0 |
| **플레이어 패배 (Run 종료)** | 아군 유닛 전원의 HP가 0 |
| **최종 목표** | 도달 스테이지 최고 기록 경신 |
| **최종 승리 조건** | **없음** (무한 진행) |

## 3. 핵심 규칙 요약

| # | 규칙 | 비고 |
| :--- | :--- | :--- |
| R-01 | 모든 생존 유닛은 **1턴에 정확히 1회** 행동한다 | SPD는 행동 **횟수**가 아니라 **순서**만 결정 |
| R-02 | 행동 순서는 매 턴 **유효 SPD 내림차순**, 동점 시 고유 ID 오름차순 | 매 턴 재정렬하므로 SPD 감소가 즉시 반영 |
| R-03 | 자기 행동 순서가 아닌 유닛은 어떤 행동도 할 수 없다 | |
| R-04 | 플레이어는 **적만** 타겟팅할 수 있다 | 아군 대상 행동 없음 |
| R-05 | 몬스터의 단일 대상 선택은 균등이 아니라 **어그로 가중 추첨**이다 | 광역기는 이 추첨을 타지 않음 (전원 대상) |
| R-06 | 데미지는 방어력 **뺄셈이 아니라 비율 감쇠**로 계산한다 | 피해가 0이 되지 않음. 최소 1 보장 |
| R-07 | 파티는 **최대 4명**이다. 꽉 찬 상태에서 영입하려면 1명을 교체해야 한다 | |
| R-08 | 죽은 아군은 **런 전체에서 영구 제거**된다 | 부활 수단 없음 |
| R-09 | 상태이상은 **전투(스테이지) 단위**다 | 스테이지를 클리어하면 전부 해제 |
| R-10 | 몬스터는 **스폰 시점에 배율**로, 플레이어는 **진급 시 flat 누적**으로 성장한다 | 플레이어는 HP를 이어받으므로 배율을 쓸 수 없음 |
| R-11 | 스테이지 클리어 시 선택지 **3종**을 제시하고 **1종**만 고를 수 있다 | 되돌리기 불가 |
| R-12 | 보스 스테이지는 **5의 배수**이며, 클리어 시 **자동 저장**된다 | 저장 시점은 선택지 수령 **전** |
| R-13 | 전멸하면 세이브가 **삭제**되고, 배틀 중단은 세이브가 **유지**된다 | 중단은 "잠시 그만둔 것" |
| R-14 | 성향 포인트는 **10 스테이지 최초 돌파마다 1점**이며, 선택지 등장 가중치에만 쓰인다 | 스탯에는 영향 없음 |

## 4. 입력 정보

### 4-1. 시스템 진입 시 입력 (Run Setup System → Battle System)

| 입력명 | 타입 | 범위 / 형식 | 출처 | 없을 때의 처리 |
| :--- | :--- | :--- | :--- | :--- |
| `StartStage` | int | ≥ 1 | 신규 = 1 / 이어하기 = 저장된 스테이지 | 1로 간주 |
| `PartyMembers` | list | 1 ~ 4명 | 캐릭터 선택 or 세이브 복원 | **오류** — 진입 차단 |
| `MemberStats` | Stats × N | 표 T1 기준 + 누적 성장 | RunData | 기준 스탯으로 복구 |
| `MemberCurrentHp` | int × N | 1 ~ MaxHp | RunData | MaxHp로 채움 |
| `ChoiceWeightPoints` | int × 9 | 각 ≥ 0, 합 ≤ 획득 총량 | SaveData | 전부 0 |
| `BestStage` | int | ≥ 0 | SaveData | 0 |

### 4-2. 턴 진행 중 입력

| 입력명 | 타입 | 조작 | 유효 조건 |
| :--- | :--- | :--- | :--- |
| 타겟 겨냥 | 대상 지정 | 마우스 클릭 / ←→ 방향키 | 플레이어 턴 & 생존 몬스터 |
| 타겟 확정 | 실행 | 겨냥된 대상 재클릭 / Enter·Space | 겨냥 상태일 때만 |
| 선택지 겨냥·확정 | 카드 1장 | 마우스 클릭 / ←→ + Enter | 보상 단계에서만 |
| 퍼즈 토글 | 토글 | ESC / HUD 버튼 | 전투 구간에서만 (보상 단계 제외) |
| 배틀 중단 | 확정 | 퍼즈 메뉴 버튼 | **연출 재생 중에는 비활성(Disabled)** |

### 4-3. 데이터 테이블 입력

전투 1회를 계산하는 데 필요한 테이블은 T1~T8 (10장) 전부입니다.

## 5. 출력 결과

### 5-1. 시스템 산출물 (데이터)

| 출력명 | 타입 | 설명 |
| :--- | :--- | :--- |
| `BattleOutcome` | enum | `Victory` / `Defeat` / `Aborted` |
| `SurvivorHp` | int × N | 생존 아군의 현재 HP (다음 스테이지로 계승) |
| `FallenMembers` | list | 사망자 목록 → 파티에서 영구 제거 |
| `AppliedChoice` | ID | 선택된 보상 ID → RunData에 즉시 반영 |
| `PendingModifiers` | 배율 | 다음 스테이지 몬스터에 1회 적용될 디버프 예약 |
| `Checkpoint` | RunSnapshot | 보스 클리어 시에만 갱신 |
| `BestStage` | int | 전멸 시 최고 기록 갱신 |

### 5-2. 플레이어에게 보여줄 결과

| 시점 | 화면 출력 |
| :--- | :--- |
| 행동 확정 | 공격 애니메이션 → 타격 파티클/SFX → 피격 모션 → 데미지 팝업(일반/치명타/도트 색 구분) → HP 바 감소(0.5초 ease-in-out) |
| 상태이상 부여 | 대상 체력바에 아이콘 + 남은 턴 수 표기 |
| 턴 전환 | 상단 턴 순서 칩 갱신 (`A1`/`E2` 배치 라벨 기준) |
| 스테이지 클리어 | 선택지 카드 3장 + 파티 스탯 갱신 |
| 보스 클리어 | 자동 저장 피드백 후 선택지 3장 |
| 전멸 | 결과 화면 (도달 스테이지 / 이전 최고 기록 / 신기록 여부) |
| 중단 | 확인 팝업 → 타이틀 복귀 |

### 6-2. 스테이지 1회의 계산 순서 (요약)

몬스터 스탯이 확정되는 순서는 **반드시** 아래와 같습니다. 순서가 바뀌면 결과가 달라집니다.

```text
기준 스탯 (T2)
   → × 스테이지 스케일링 배율      (F-2)
   → × 예약된 디버프 배율          (F-8)   ※ 적용 후 배율 1로 소모
   → 확정 (전투 중 변경 없음)
   → 상태이상 감소는 조회 시점에만 반영 (F-7b)
```

파티 스탯이 확정되는 순서:

```text
기준 스탯 (T1)
   → + 자동 성장 누적분            (F-3)
   → + 선택지 성장 누적분          (F-5)
   → + 파티 시너지 (전투 중에만)    (F-6)
   → 상태이상 감소는 조회 시점에만 반영 (F-7b)
```

### F-1. 데미지 계산 (비율 감소 + 치명타)

**필요한 이유** — 방어력을 뺄셈으로 처리하면 `ATK ≤ DEF`인 순간 피해가 0이 됩니다. 비율 감쇠는 방어력이 아무리 높아도 피해가 0이 되지 않으면서, 올릴수록 수익이 체감해 무한 성장을 자연스럽게 억제합니다.

**입력** — 공격자 유효 ATK, 대상 유효 DEF, 스킬 배율 `m`(일반 공격 = 1.0), 공격자 CritRate/CritDmg, 난수
**출력** — 정수 피해량, 치명타 여부

```
감쇠     = K / (K + DEF_eff)                       (K = 1000)
기본피해 = ATK_eff × 감쇠 × m
최종피해 = 기본피해 × CritDmg   (rng < CritRate)
         = 기본피해            (그 외)
피해량   = max(1, round(최종피해))
```

**예시 계산**

| 케이스 | 입력 | 계산 | 결과 |
| :--- | :--- | :--- | :--- |
| 일반 | Knight ATK 200 → Minion DEF 80, m=1.0 | `1000/(1000+80)=0.9259` → `200×0.9259×1.0=185.19` | **185** |
| 치명타 | 위와 동일, CritDmg 1.5 | `185.19×1.5=277.79` | **278** |
| 보스 스킬 | Warrior ATK 230 → Knight DEF 150, m=1.8 | `1000/1150=0.8696` → `230×0.8696×1.8=360.0` | **360** |
| 방어 관통 | Mage ATK 350 → Warrior DEF 200, m=1.0 | `1000/1200=0.8333` → `350×0.8333=291.7` | **292** |

**상한/하한** — 최소 1, 최대 없음
**밸런스 의도** — `K`는 "피해가 절반이 되는 DEF 값"입니다. `K=1000`이고 현재 DEF 구간이 10~200이라 감쇠는 0.83~0.99 — 방어력의 영향이 의도적으로 완만합니다. 치명타 기대 배율은 `(1−Rate) + Rate×Dmg`이며, Rogue(Dagger)는 1.75배, Knight는 1.125배입니다.
**⚠ 주의** — `K`는 스탯 스케일과 함께 움직여야 합니다. 스탯만 10배 하고 `K`를 두면 방어력이 10배 세져 전투가 늘어집니다.

### F-2. 몬스터 스테이지 스케일링

**필요한 이유** — 무한 진행이라 "언젠가는 못 이기는 벽"이 필요합니다.

**입력** — 몬스터 기준 스탯, 현재 스테이지, 성장률·복리 토글·가속 파라미터 (T6)
**출력** — 스폰 시점의 몬스터 Stats (치명타·저항은 변경 없음)

```
steps       = max(0, stage − 1)
normalSteps = min(steps, accelStart − 1)
accelSteps  = steps − normalSteps

배율(복리 ON)  = (1+rate)^normalSteps × (1 + rate×accelMul)^accelSteps
배율(복리 OFF) = 1 + rate×normalSteps + rate×accelMul×accelSteps

결과 = max(1, round(기준값 × 배율))
```

SPD만 별도 규칙입니다 (가속 미적용):

```
spdSteps = floor( max(0, stage − spdStart) / interval )
SPD      = max(1, round( SPD_base × (1 + rate_spd)^spdSteps ))
```

**예시 계산**

| 스테이지 | 계산 (Minion HP 500, rate 0.10, 복리 ON) | 결과 |
| :--- | :--- | :--- |
| 1 | `steps=0` → 배율 1.0 | **500** |
| 10 | `1.10^9 = 2.358` | **1,179** |
| 30 | `1.10^29 = 15.86` | **7,930** |
| 36 | `1.10^29 × 1.20^6 = 15.86 × 2.986 = 47.36` | **23,680** |
| 36 (가속 없었다면) | `1.10^35 = 28.10` | 14,050 |

**상한/하한** — 최소 1, 최대 없음 (복리라 발산)
**밸런스 의도** — 몬스터 성장률이 플레이어보다 높은 것이 전제입니다. 가속 구간을 30스테이지에서 끊는 이유는, 성장률만 통째로 올리면 초반까지 함께 어려워지기 때문입니다. SPD에 가속을 적용하지 않는 이유는 가속 구간에서 속도까지 튀면 선공이 한순간에 뒤집혀 대응할 여지가 없기 때문입니다.
**⚠ 주의** — HP 성장률은 "전투가 몇 라운드짜리인가"를, ATK 성장률은 "실수했을 때의 전멸 위험도"를 움직입니다. 둘을 혼동하면 엉뚱한 값을 만지게 됩니다.

### F-3. 플레이어 자동 성장 (누적 차분)

**필요한 이유** — 플레이어는 현재 HP를 스테이지 간 이어받으므로 배율을 곱하면 현재 HP와 최대 HP가 어긋납니다. 그래서 flat 증가분을 누적합니다. 또 매 스테이지 따로 반올림하면 오차가 쌓이므로 **누적 총량의 차분**을 돌려줍니다.

```
G(step)  = round(base × rate × step)
ΔG(step) = G(step) − G(step−1)
```

SPD는 **보스를 잡았을 때만** 증가하며, 횟수가 `step`이 아니라 지나온 보스 수입니다:

```
B(step)    = floor(step / interval)
ΔSPD(step) = G_spd(B(step)) − G_spd(B(step−1))
```

**예시 계산**

| 항목 | 입력 | 계산 | 결과 |
| :--- | :--- | :--- | :--- |
| DEF 3스텝 | Knight DEF 150, rate 0.03 | `G = 4, 9, 14` → 차분 `4, 5, 5` | 누적 **+14** (이론값 13.5) |
| 잘못된 방식 비교 | 매 스텝 따로 반올림 | `round(4.5)×3 = 4+4+4` | 12 (2만큼 낮게 굳음) |
| SPD | Knight SPD 100, 보상률 0.08, 간격 5 | 5스테이지: `B` 0→1 → **+8** / 6~9: 0 / 10스테이지: **+8** | 보스마다 +8 |

**상한/하한** — 최소 0, 최대 없음
**밸런스 의도** — 성장 기준이 현재 스탯이 아니라 **캐릭터 기준 스탯**입니다. 그래서 선택지로 한 스탯을 몰아줘도 자동 성장분이 함께 부풀지 않습니다. **SPD는 자동 성장 대상이 아니므로** 플레이어가 SPD를 얻는 경로는 보스 보상과 속도 강화 선택지 둘뿐이고, 이것이 속도 강화 선택지에 가치를 부여합니다.
**⚠ 주의** — "매 스테이지 최소 +1" 같은 바닥값을 넣으면 저스탯 캐릭터가 비정상적으로 급성장합니다(과거 실제 문제).

### F-4. 영입자 소급 성장 (Catch-up)

**필요한 이유** — 후반에 합류한 캐릭터가 1스테이지 기준 스탯 그대로면 즉시 전력 외가 됩니다.

```
Stats_합류 = base + Σ(s=1 → stage−1) ΔG(s) = base + G(stage−1)
```

**예시 계산** — Barbarian ATK 270, rate 0.04, 11스테이지 영입 → `G(10) = round(270 × 0.04 × 10) = 108` → ATK **378**로 합류

**상한/하한** — 최소 = 기준 스탯 그대로(1스테이지 영입), 최대 없음
**밸런스 의도** — **선택지 성장은 소급하지 않습니다.** "그건 그 시점 파티가 벌어들인 몫"이며, 파티원을 살려두는 데 가치를 두기 위한 설계입니다. 따라서 새 영입자가 기존 파티원보다 약한 것은 **버그가 아니라 규칙**입니다.

---

### F-5. 선택지 성장 (비율, 혼합 모델)

**필요한 이유** — 무한 진행이라 고정 증분은 후반에 반드시 무의미해집니다. 다만 **현재 스탯**을 기준으로 삼으면 복리가 되어 한 스탯 몰아주기가 압도적으로 유리해지고, **기준 스탯**만 쓰면 고정 증분과 다를 바 없어집니다. 그래서 기준을 그 중간에 둡니다.

```
기준스탯 = Stats − ChoiceGrowth          (= 기준값 + 자동 성장)

Stat += round(기준스탯 × rate)            (HP / ATK / SPD / DEF)
Stat  = min(1, Stat + Δ)                 (치명타율 / 저항)
Stat += Δ                                (치명타 피해)
HP   += round(MaxHp_실제 × healRate)      (회복만 실제 MaxHp 기준)
```

**예시 계산** — Barbarian(기준 ATK 270)이 `공격력 강화`(ATK +45%)를 획득

| 획득 시점 | 기준스탯 | 계산 | 증가분 |
| :--- | :--- | :--- | :--- |
| 1스테이지 | 270 | `round(270 × 0.45)` | **+122** |
| 30스테이지 | `270 × (1 + 0.04×29) ≈ 583` | `round(583 × 0.45)` | **+262** |

같은 선택지가 후반에 2배 이상의 값을 갖습니다. 고정 증분이었다면 두 경우 모두 같은 값이었을 것입니다.

**상한/하한** — 최소 0(바닥값 없음), 치명타율·저항은 100% 클램프, 치명타 피해는 상한 없음
**⚠ 주의** — 회복만 기준이 다릅니다. 성장은 `기준스탯`, 회복은 **실제 MaxHp**입니다. 플레이어가 체력바에서 보는 최대치와 어긋나면 안 되기 때문입니다.

---

### F-6. 파티 시너지 (혼합 모델)

**필요한 이유** — 같은 캐릭터를 중복 영입하는 선택에 보상을 줍니다. 정수 스탯은 비율로 줘야 후반에도 의미가 남습니다.

**발동 조건** — 같은 캐릭터가 `SynergyThreshold`(전원 2) 이상 파티에 존재. 보너스는 **그 캐릭터들에게만** 적용됩니다.

```
Stat += round(Stat × rate)     (ATK / SPD / DEF)
Stat  = min(1, Stat + Δ)       (치명타율 / 저항)
Stat += Δ                      (치명타 피해)
```

**예시 계산** — Knight 2명, DEF 150, 시너지 DEF +100%
`150 + round(150 × 1.0) = 300` → 감쇠가 `1000/1150 = 0.870`에서 `1000/1300 = 0.769`로
→ DEF **300**, 받는 피해 **−11.6%** (실효 HP +13%)

**상한/하한** — 최소 0(수치가 전부 0이면 시너지 없는 캐릭터), 치명타율·저항 100% 클램프
**적용/해제** — 런 데이터에 누적하지 않고 **전투 중에만** 얹었다 뗍니다. 대상이 죽어 인원이 임계치 미만이 되면 **즉시** 해제합니다(B-14).
**⚠ 주의** — 표시된 %를 스탯끼리 비교하면 안 됩니다. `ATK +20%`는 피해 +20%지만 `DEF +100%`는 감쇠 때문에 받는 피해 −11.6%뿐이고, SPD는 순서만 바꾸므로 전투력 환산 가치가 가장 낮습니다.

---

### F-7a. 상태이상 부여 확률 (RES 저항)

```
P(성공) = ApplyChance × (1 − clamp(RES, 0, 1))
```

**예시 계산** — Warrior 스킬 기절(0.35) → Knight RES 0.2 → `0.35 × 0.8 = 0.28` → **28%**

**상한/하한** — 최소 0 (RES 100% = 완전 면역), 최대 = ApplyChance 그대로 (RES 0)
**⚠ 주의** — 로그라이크 **디버프 선택지는 이 공식을 타지 않습니다.** 저항 판정 없이 확정 부여합니다. 플레이어가 선택을 소모해 얻은 효과가 몬스터 RES로 헛돌면 선택의 가치가 무너지기 때문입니다.

### F-7b. 상태이상 스탯 감소

```
Stat_eff = max(0, round( Stat_base × (1 − min(1, Magnitude)) ))
```

**예시 계산** — Knight DEF 150, DefDown Magnitude 0.5 → `150 × 0.5 = 75` → 유효 DEF **75** (원본 DEF는 150 그대로)

**⚠ 주의** — 원본 `Stats`를 직접 고치지 않고 **조회 시점에** 반영합니다. 파티 시너지가 이미 `Stats`를 스냅샷/복원 방식으로 조작하므로, 양쪽이 같은 필드를 쓰면 서로를 덮어씁니다. 데미지 계산과 턴 순서가 이 유효 스탯을 쓰고, **치명타 판정만 원본 CritRate**를 봅니다.

---

### F-8. 몬스터 디버프 배율 중첩 (다음 스테이지 예약)

```
누적배율 ×= 선택지배율
몬스터스탯 = max(1, floor( Stat × 누적배율 ))
적용 후 ⇒ 누적배율 = 1                      (소모)
```

**예시 계산** — `체력 감소`(0.7)를 같은 런에서 연속 2회 획득 → `0.7 × 0.7 = 0.49` → Minion HP 500 → **245** (51% 감소)

**적용 순서** — 기준 스탯 → 스테이지 스케일링 → **디버프**. 즉 디버프는 이미 성장한 값에 곱해집니다.
**⚠ 주의** — 이 공식만 반올림이 아니라 **내림(floor)**입니다. 또 `몬스터 행동불가`는 배율이 아니라 **기절 1턴 확정 부여**로 처리됩니다.

### F-8b. 도트(중독) 피해

```
피해 = max(1, round( MaxHp × Magnitude ))
```

**예시 계산** — Knight MaxHp 1000, Poison Magnitude 0.05 → 턴당 **50** (3턴 지속 = 총 150 = 최대 HP의 15%)

**밸런스 의도** — 최대 HP 비율이라 탱커에게 더 아픕니다. 방어형 캐릭터의 카운터로 기능합니다.
**⚠ 주의** — 처리 순서가 곧 규칙입니다. **도트 → 지속 턴 감소 → 기절 판정** 순서여야 도트로 죽은 유닛이 그 차례에 행동하지 못합니다.

---

### F-9. 선택지 등장 가중치

```
W_기본 = max(0, w + w_slot × max(0, 빈자리수))
W_최종 = W_기본 + P_투자 × w_point            (w_point = 1)
```

**예시 계산**

| 상황 | 영입 가중치 | 나머지 8종 | 영입 등장 확률 |
| :--- | :--- | :--- | :--- |
| 파티 1명 (빈자리 3), 투자 0 | `1 + 4×3 = 13` | 각 1 | **13 / 21 = 62%** |
| 파티 4명 (빈자리 0), 투자 0 | `1 + 4×0 = 1` | 각 1 | 1 / 9 = 11% |
| 파티 4명, 공격력에 2점 투자 | 1 | 공격력 3, 나머지 각 1 | 공격력 3 / 11 = 27% |

**상한/하한** — 최소 0, 최대 없음
**⚠ 주의** — 포인트 1점이 가중치 +1이라, 기본 가중치가 1인 현재 값에서는 1점의 영향이 **2배**로 매우 큽니다. 12장 위험 R-05 참조.

### F-10. 중복 없는 가중치 추첨

```
P(i) = max(0, w_i) / Σ(k ∈ 남은 후보) max(0, w_k)
```

한 항목을 뽑을 때마다 후보에서 제거하고 남은 것끼리 다시 정규화합니다. 가중치 합이 0 이하이면 **균등 추첨**으로 대체합니다(E-12).

**예시 계산** — 가중치 `[13, 1, 1, 1]`에서 2개 추첨
1차: 합 16 → 첫 항목이 `13/16 = 81%`. 뽑히면 남은 `[1,1,1]`이 각 `1/3`로 재정규화

**사용처** — 선택지 3종, 영입 후보 3명, 랜덤 웨이브 1종

---

### F-11. 어그로 가중 대상 선택

**필요한 이유** — 균등 추첨이면 방어형을 파티에 넣어도 마법사가 똑같은 확률로 맞아, "누구를 앞에 세울까"라는 판단이 생기지 않습니다.

```
P(i) = max(0, w_i) / Σ(k ∈ 생존) max(0, w_k)
```

**예시 계산** — Knight(4) / Barbarian(3) / Mage(1) / Ranger(1), 합 9

| 상태 | Knight | Barbarian | Mage | Ranger |
| :--- | :--- | :--- | :--- | :--- |
| 전원 생존 (합 9) | **44%** | 33% | 11% | 11% |
| Knight 사망 (합 5) | — | **60%** | 20% | 20% |

후보 목록이 곧 생존자이므로 **자동으로 재정규화**됩니다. 별도 처리가 없습니다.

**상한/하한** — 최소 0(사실상 표적이 되지 않음), 최대 없음
**밸런스 의도** — 절대값이 아니라 **서로의 배수**가 의미를 갖습니다. 전열:후열 = 3:1이면 전열 1명이 후열 1명보다 3배 자주 맞습니다. 후열을 0으로 두지 않는 이유는, 요구가 "확률이 더 높다"이지 "전열만 맞는다"가 아니기 때문입니다.
**⚠ 주의** — 광역기(`Line`)는 이 공식을 타지 않습니다. 후보 전원이 대상입니다.

---

### F-12. 턴 순서 정렬

```
1순위: 유효 SPD 내림차순
2순위: 고유 ID 오름차순 (안정적 타이브레이커)
```

**예시 계산** — Rogue_Dagger(150) / Knight(100) / Minion(70) → **Rogue → Knight → Minion**

**밸런스 의도** — 매 턴 재정렬하므로 SPD 감소 상태이상이 즉시 반영됩니다. **모든 유닛이 턴당 정확히 1회 행동**하므로 SPD는 "몇 번 행동하는가"가 아니라 "누가 먼저인가"만 결정합니다. SPD 투자 가치를 평가할 때 이 점이 핵심입니다.
**⚠ 주의** — 동속일 때 ID 순서상 항상 적이 먼저 행동할 수 있습니다(E-18 / 위험 R-04).

---

### F-13. 보스 웨이브 판정

```
보스 여부 = (stage mod interval == 0)        (interval = 5)
```

수동 설계 웨이브 범위(1~5) 안이면 그 구성을 그대로 쓰고, 그 이후는 보스 여부에 따라 보스 풀 / 일반 풀에서 가중치 추첨합니다.

**예시 계산** — 10스테이지, 간격 5, 수동 웨이브 5개 → `10 > 5`(랜덤 구간) & `10 mod 5 = 0`(보스) → **보스 풀에서 추첨**

**⚠ 주의** — 보스 BGM 등의 "보스 웨이브" 판정은 **보스 등급(Tier=Boss) 몬스터가 포함됐는지**로 정합니다. 스테이지 번호 배수가 아닙니다. 강한 일반 몬스터만으로 구성된 웨이브는 보스 웨이브 취급이 아닙니다. 현재 데이터는 5의 배수마다 반드시 보스가 포함되도록 설계돼 있습니다.

---

### F-14. 영구 포인트 획득 / 잔여

```
획득 = floor( BestStage / stagesPerPoint )      (stagesPerPoint = 10)
잔여 = 획득 − Σ 투자
```

**예시 계산** — BestStage 37, 공격력에 1점 투자 → 획득 `37/10 = 3` → 잔여 `3 − 1 = 2` → 화면 표기 **"보유 2 / 총 3"**

**상한/하한** — 최소 0, 최대 없음
**밸런스 의도** — 획득량을 저장하지 않고 최고 기록에서 **파생**시켜 두 값이 어긋날 여지 자체를 없앴습니다. 리스펙은 무료입니다 — 투자를 되돌리는 데 비용이 없어 실험을 막지 않습니다.

## 부록 B. 5분 발표용 요약

```text
1. 게임 가제와 선택한 시스템
   Endless Expedition — 턴제 JRPG + 로그라이크 무한 타워
   선택 시스템: Battle System (조우 진입 → 보상 반영)

2. 시스템 목적
   아이템·경험치 없이 "누구를 때릴까" + "무엇을 고를까" 두 판단만으로
   무한히 어려워지는 스테이지를 얼마나 버티는지를 겨룬다.

3. 코어 메카닉스
   - 전투: SPD 순서 → 타겟 지정 → 확정
   - 보상: 클리어 시 3종 중 1종 선택 (즉시 반영, 되돌리기 없음)
   - 배제: 장비 / 아이템 / 경험치 (복잡도를 낮춰 두 판단에 집중)

4. 기본 흐름과 조건 분기
   스폰 → 턴 정렬 → [상태이상 → 행동 → 판정] × N → 종료 판정 → 보상
   분기: 보스(5의 배수) / 난이도 가속(30+) / 스킬 쿨타임 / 시너지 발동
   예외: 사망 시 영구 제거, 전멸 시 세이브 삭제, 중단 시 세이브 유지

5. 사용 공식과 예시 계산  (전체 14종 중 대표 3종)
   ① 데미지 = max(1, round(ATK × K/(K+DEF) × m × [crit]))
      Knight 200 → Minion DEF 80 : 200 × 0.9259 = 185
   ② 몬스터 성장 = 기준값 × (1+r)^n × (1+r×2)^가속n
      Minion HP 500 → 36스테이지 : 23,680  (가속 없으면 14,050)
   ③ 선택지 성장 = round((현재Stats − 선택지누적) × rate)
      Barbarian ATK +45% : 1스테이지 +122 / 30스테이지 +262

6. 사용 데이터 테이블
   T1 캐릭터 6 / T2 몬스터 4 / T3 스킬 3 / T4 상태이상 5
   T5 선택지 9 / T6 스케일링 12 / T7 웨이브 12 / T8 상수 8
   ID 대역: 1000 캐릭터 · 2000 몬스터 · 3000 스킬 · 4000 상태이상
            5000 선택지 · 6000 스케일링 · 7000 웨이브 · 9000 상수

7. 예외 상황과 테스트 조건
   예외 20종 / 테스트 39건 (정상 12 · 실패 7 · 예외 20)
   대표: 도트 사망 시 그 차례 행동 소멸 / 연출 중 배틀 중단 잠금
         가중치 전부 0이면 균등 추첨 / RES 100% 완전 면역

8. 리뷰 후 수정한 내용
   - "적이 가파르게 성장"을 구체 수치 + 증가 방식(복리/선형)으로 교체
   - "5의 배수 보스"와 "보스 웨이브 판정"이 서로 다른 기준임을 분리
   - 상태이상 처리 순서(도트 → 턴 감소 → 기절)를 흐름도에 명시
   - 배틀 중단 잠금 조건을 "퍼즈 중"이 아닌 "연출 재생 중"으로 정정
   - xlsx 원본과 최신 값의 차이 7건을 표로 등록 (부록 A-2-1)
```
