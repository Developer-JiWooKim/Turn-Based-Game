# 최종 시스템 기획서 — Endless Expedition

## 1. 시스템 이름

**전투 & 로그라이크 보상 시스템 (Battle & Roguelike Reward System)**

---

## 2. 시스템 목적

> 플레이어가 `전투 중 타겟팅 판단`과 `스테이지 클리어 후 3종 선택지 판단`만으로 파티를 성장시키며, 지수적으로 강해지는 몬스터를 상대로 최대한 많은 스테이지를 돌파하게 하는 시스템이다.

- 장비/아이템/EXP를 의도적으로 배제하여, 성장 경로를 **선택지 단 하나**로 수렴시킨다.
- 몬스터의 성장률(지수)이 플레이어 자동 성장률(선형)보다 높게 설계되어 있으므로, 플레이어는 반드시 선택지를 통한 **집중 특화 빌드**를 구성해야 한다. 

---

## 3. 핵심 규칙 요약

| 번호 | 규칙 |
| :--- | :--- |
| 1 | 모든 유닛은 1턴에 정확히 1회 행동한다.|
| 2 | 턴 순서는 매 턴 재정렬한다. 1순위 유효 SPD 내림차순, 2순위 고유 ID 오름차순. |
| 3 | 자신의 행동 순서에 도달하지 않은 유닛은 임의 행동이 불가하다. |
| 4 | 공격/스킬의 타겟은 항상 적군만 가능하다. 아군 대상 지정은 불가하다. |
| 5 | 파티원은 최대 4명이다. 4명 상태에서 영입 시 기존 파티원 1명을 반드시 대체해야 한다. |
| 6 | 아군 사망 시 파티에서 영구 제거되며, 시너지 조건 미달 시 시너지는 즉시 해제된다. |
| 7 | 5의 배수 스테이지는 보스 웨이브이며, 클리어 시 선택지 제시 **이전**에 자동 저장한다. |
| 8 | 파티 전멸 시 세이브 데이터를 영구 삭제하고 최고 기록을 갱신한다. |
| 9 | 스테이지 클리어 시 9종 선택지 중 가중치 추첨으로 3종을 중복 없이 제시하고, 플레이어는 반드시 1종을 선택한다. |
| 10 | 상태이상은 전투(스테이지) 단위로만 유지되며, 스테이지 클리어 시 전부 해제된다. |
| 11 | 유닛이 행동 중에는 Pause 메뉴의 [배틀 중단] 버튼이 비활성화된다. |

## 4. 입력 정보

### 런타임 입력 (직전 시스템(Save Data)/이전 스테이지에서 인계)

| 입력명 | 자료형 | 설명 |
| :--- | :--- | :--- |
| `Stage_Index` | int | 현재 스테이지 번호 (1 이상) |
| `Party_Data` | list | 파티원 목록(최대 4), 각 유닛의 현재 HP / 누적 선택지 성장분 / 시너지 |
| `Choice_Weight` | dict | 선택지 카테고리별 투자 포인트 (Run Setup에서 배분) |
| `Pending_Enemy_Debuff` | float×2 | 이전 스테이지 선택지로 예약된 몬스터 HP/ATK 배율 |
| `Best_Stage` | int | 저장된 최고 스테이지 기록 (영구 포인트 산출용) |

### 플레이어 입력

| 단계 | 입력 | 대응 조작(Default) |
| :--- | :--- | :--- |
| 전투 | 타겟 지정 | 마우스 클릭 / 키보드 방향키(좌·우) |
| 전투 | 공격·스킬 확정 | 마우스 클릭 / Space / Enter |
| 보상 | 선택지 선택·확정 | 마우스 클릭 / 키보드 방향키(좌·우) |

- 키 입력은 유저가 임의로 바꿀 수 있도록 기능을 제공한다.

## 6. 기본 흐름

```
1) [조우 진입]   Stage_Index로 웨이브 구성 판정 → 몬스터 스폰
                 (기준 스탯 → 스테이지 스케일링 → 예약 디버프 배율 순으로 적용)
2) [턴 정렬]     생존 전원의 유효 SPD 비교 → 행동 큐(Queue) 생성
3) [턴 수행]     Queue 순서대로 1유닛씩 행동
                   3-1) 턴 시작 처리: 도트 피해 → 지속 턴 감소 → 기절 판정
                   3-2) Player Turn: 타겟팅 입력 → 공격/스킬 확정 → 데미지 연산 → 연출
                        Enemy Turn : 어그로 가중치 추첨으로 타겟 선정 → 동일 연산
                   3-3) 사망 판정 (HP 0 도달 시 즉시 제거)
4) [턴 순환]     Queue 전원 행동 완료 → 턴 종료 → 2)로 복귀(SPD 재정렬)
5) [조우 클리어] 적 전멸 → 상태이상 전부 해제
                   5-1) 보스 스테이지였다면 자동 저장
                   5-2) 선택지 가중치 산출 → 중복 없는 3종 추첨 → UI 출력
                   5-3) 플레이어 선택 1종 반영
6) [다음 진행]   Stage_Index += 1 → 플레이어 자동 성장 차분 적용 → 1)로 복귀
```

## 7. 조건 분기

| 조건 | 처리 |
| :--- | :--- |
| `stage ≤ 5` | 수동 설계 웨이브 구성을 그대로 사용(Tutorial Wave) |
| `stage > 5` 이고 `stage % 5 ≠ 0` | 일반 몬스터 풀에서 가중치 추첨 |
| `stage % 5 == 0` | 보스 풀에서 추첨(보스급 몬스터 반드시 포함), 보스 BGM 재생 |
| 보스 스테이지 클리어 | 선택지 제시 **전** 자동 저장(Party_Data / Stage_Index / Weight), 저장 알림 표시 |
| 일반 스테이지 클리어 | 저장 없이 즉시 다음 스테이지 진행 |
| 보스 스테이지 클리어 (플레이어 성장) | 플레이어 SPD 보상 차분 적용 (+기준 SPD의 8%), 다음 스테이지부터 몬스터 SPD 12% 복리 증가 |
| 선택지 = 영입, 파티 인원 < 4 | 교체 절차 없이 즉시 합류 (소급 성장 적용) |
| 선택지 = 영입, 파티 인원 = 4 | 교체 대상 선택 UI 출력 → 대체 확정 |
| 선택지 = 적 디버프 | 즉시 적용이 아니라 **다음 스테이지 1회** 예약, 배율은 곱연산 누적 |
| 선택지 = 적 행동불가(EnemyStun) | 배율이 아닌 기절 1턴 확정 부여로 처리 |
| 스킬 Scope = Line(광역) | 어그로 가중치 추첨을 타지 않고 후보 전원이 대상 |

## 8. 예외 상황

| 상황 | 처리 |
| :--- | :--- |
| 아군 1인 HP 0 도달 | 파티에서 즉시 영구 제거. 시너지 조건 미달 시 시너지 즉시 해제. 남은 인원으로 전투 계속 |
| 아군 전원 사망 (Game Over) | 전투 즉시 종료 → 결과 화면 → 세이브 영구 삭제 → 최고 기록 갱신 → Meta_Point 지급 → 타이틀 복귀 |
| 도트 피해로 사망 | 행동 실행 **전**에 사망 처리. 해당 유닛은 그 차례에 행동하지 못함 |
| 플레이어 턴 중 [배틀 중단] 클릭 | 확인 팝업(`"현재 진행은 저장되지 않으며, 마지막 저장 지점부터 시작합니다."`) → 확인 시 마지막 Auto-Save 유지 상태로 타이틀 복귀 |
| 적 턴 중 Pause 진입 | Pause UI는 열리되 [배틀 중단] 버튼은 Disabled 처리 |
| 공격 연출 진행 중 [배틀 중단] 클릭 | 입력 무시 (버튼 비활성) |
| 동일 상태이상 재부여 | 지속 턴·Magnitude 각각 **더 큰 값**으로 갱신. 약한 재부여가 강한 상태를 덮어쓰지 않음 |
| 선택지 가중치 총합 ≤ 0 | 균등 추첨으로 대체 (아무것도 뜨지 않는 상황 방지) |
| 어그로 가중치 총합 ≤ 0 | 균등 추첨으로 대체 |
| 부동소수 오차로 추첨 구간 미선택 | 마지막 후보로 폴백 (의도된 동작) |
| 영입 후보 로스터가 비어 있음 | 교체 여부 확인 절차를 생략하고 즉시 영입 |
| 파티 인원 4명 + 영입 선택지 등장 | 후보에서 제외하지 않음. 빈자리 보정만 사라져 상대적으로 드물게 등장 |

## 9. 사용 공식

전체 14종. 상세 유도와 밸런스 의도는 `SystemFormulaBalance.md` 참조.

### 9-1. 데미지 계산 (비율 감소 + 치명타)

```
감쇠     = K / (K + DEF_eff)                    // K = 1000
기본피해 = ATK_eff × 감쇠 × m                    // m = 스킬 배율, 일반 공격 1.0
최종피해 = rng < CritRate ? 기본피해 × CritDmg : 기본피해
피해량   = max(1, round(최종피해))
```

- **예시:** Knight(ATK 200) → Skeleton_Minion(DEF 80), 일반 공격, 비치명타
  `1000 / (1000+80) = 0.9259` → `200 × 0.9259 × 1.0 = 185.19` → **185**
  (치명타 시 `185.19 × 1.5 = 277.8` → **278**)
- **상한/하한:** 하한 1 / 상한 없음
- **주의:** K는 스탯 스케일과 함께 움직여야 한다. 스탯만 10배 하고 K를 두면 방어력이 10배 강해져 전투가 늘어진다.

### 9-2. 몬스터 스테이지 스케일링

```
steps       = max(0, stage - 1)
normalSteps = min(steps, accelStart - 1)        // accelStart = 30
accelSteps  = steps - normalSteps
배율(복리ON) = (1+rate)^normalSteps × (1 + rate×accelMul)^accelSteps   // accelMul = 2.0
결과        = max(1, round(기준값 × 배율))

// SPD는 가속 미적용, 보스 처치 시에만 상승
spdSteps = floor(max(0, stage - spdStart) / interval)   // spdStart = 1, interval = 5
SPD      = max(1, round(SPD_base × (1 + 0.12)^spdSteps))
```

- **예시:** Skeleton_Minion HP 500, 36스테이지, HP 성장률 0.10, 복리 ON
  `steps=35, normalSteps=29, accelSteps=6` → `1.10^29 = 15.86`, `1.20^6 = 2.986` → 배율 `47.36` → **23,680**
  (가속이 없었다면 `1.10^35 = 28.10` → 14,050)
- **상한/하한:** 하한 1 / 상한 없음(복리이므로 발산)
- **주의:** HP 성장률은 "전투가 몇 라운드짜리인가", ATK 성장률은 "한 방의 위험도"를 움직인다. 둘을 혼동하면 엉뚱한 값을 만지게 된다.

### 9-3. 플레이어 자동 성장 (누적 차분)

```
G(step)  = round(base × rate × step)
ΔG(step) = G(step) - G(step-1)

// SPD는 보스 처치 시에만
B(step)    = floor(step / interval)
ΔSPD(step) = G_spd(B(step)) - G_spd(B(step-1))
```

- **예시:** Knight DEF 150, rate 0.03 (스텝당 4.5)
  `G = 4, 9, 14` → 차분 **4, 5, 5** → 3스텝 후 누적 **+14** (이론값 13.5에 근접)
  매 스텝 따로 반올림했다면 `4+4+4 = 12`로 2만큼 낮게 굳었을 것
- **SPD 예시:** Knight SPD 100, 보상률 0.08 → 5스테이지에서 **+8**, 6~9스테이지 0, 10스테이지에서 다시 **+8**
- **상한/하한:** 하한 0 / 상한 없음
- **주의:** "매 스테이지 최소 +1" 같은 바닥값을 넣지 말 것. 영입 소급 성장이 이 함수를 step 1부터 되짚어 호출하므로 여기를 바꾸면 영입자 스탯도 함께 바뀐다.

### 9-4. 영입자 소급 성장 (Catch-up)

```
Stats_합류 = base + Σ(s=1..stage-1) ΔG(s) = base + G(stage-1)
```

- **예시:** Barbarian ATK 270, rate 0.04, 11스테이지 영입 → `G(10) = round(270 × 0.04 × 10) = 108` → ATK **378**로 합류
- **상한/하한:** 하한 = 기준 스탯 그대로(1스테이지 영입) / 상한 없음
- **밸런스 의도:** 선택지 성장분은 소급하지 않는다. 그 시점 파티가 벌어들인 몫이며, 파티를 살려두는 데 가치를 두기 위함이다.

### 9-5. 로그라이크 선택지 성장 (비율, 혼합 모델)

```
기준스탯 = Stats - ChoiceGrowth        // = 기준값 + 자동 성장분
Stat += round(기준스탯 × rate)          // HP/ATK/SPD/DEF
Stat  = min(1, Stat + Δ)               // 치명타율/저항 (100% 클램프)
Stat += Δ                              // 치명타 피해 (상한 없음)
HP   += round(MaxHp_실제 × healRate)    // 회복만 실제 MaxHp 기준
```

- **예시:** Barbarian(기준 ATK 270), 공격력 강화(비율 0.45)를 1스테이지 / 30스테이지에서 각 1회
  1스테이지 → `round(270 × 0.45) = +122`
  30스테이지 → 기준이 `270 × (1 + 0.04×29) ≈ 583`이므로 `round(583 × 0.45) = +262`
  → 같은 선택지가 후반에 2배 이상의 값을 갖는다
- **상한/하한:** 하한 0 / 치명타·저항은 100% 클램프, 치명타 피해는 상한 없음
- **주의:** 성장은 "기준스탯", 회복은 "실제 MaxHp"로 기준이 다르다.

### 9-6. 파티 시너지 (혼합 모델)

```
Stat += round(Stat × rate)      // ATK/SPD/DEF
Stat  = min(1, Stat + Δ)        // 치명타/저항
Stat += Δ                       // 치명피해
```

- **예시:** Knight 2명, DEF 150, 시너지 DEF +100% → `150 + 150 = 300`
  감쇠가 `1000/1150 = 0.870` → `1000/1300 = 0.769` → 받는 피해 **−11.6%** (실효 HP +13%)
- **적용 범위:** 전투용 Stats에만 얹히며 런 데이터에 누적되지 않는다.
- **주의:** 표시된 %를 스탯끼리 비교하면 안 된다. ATK +20%는 피해 +20%지만 DEF +100%는 받는 피해 −11.6%뿐이고, SPD는 순서만 바꾸므로 전투력 환산 가치가 가장 낮다.

### 9-7. 상태이상 부여 확률 (RES 저항)

```
P_성공 = ApplyChance × (1 - clamp(RES, 0, 1))
```

- **예시:** Skeleton_Warrior 기절(0.35) → Knight RES 0.2 → `0.35 × 0.8 = 0.28` → **28%**
- **상한/하한:** 하한 0(RES 100% = 완전 면역) / 상한 = ApplyChance
- **주의:** 로그라이크 디버프 선택지는 이 공식을 **타지 않는다**. 저항 판정 없이 확정 부여한다.

### 9-8. 상태이상 스탯 감소

```
Stat_eff = max(0, round(Stat_base × (1 - min(1, Magnitude))))
```

- **예시:** Knight DEF 150, DefDown 0.5 → 유효 DEF **75** (원본 150은 유지)
- **주의:** 데미지 계산과 턴 순서는 이 유효 스탯을 쓴다. 치명타 판정만 원본 CritRate를 본다.

### 9-9. 도트(중독) 피해

```
피해 = max(1, round(MaxHp × Magnitude))
```

- **예시:** Knight MaxHp 1000, Poison 0.05 → 턴당 **50** (3턴 지속 시 총 150 = 최대 HP의 15%)
- **밸런스 의도:** 최대 HP 비율이므로 탱커에게 더 아프다. 방어형 캐릭터의 카운터로 기능한다.

### 9-10. 몬스터 디버프 배율 중첩 (다음 스테이지 예약)

```
누적배율 ×= 선택지배율
몬스터스탯 = max(1, floor(Stat × 누적배율))
적용 후 → 누적배율 = 1
```

- **예시:** 체력 감소(0.7)를 같은 스테이지에서 2회 획득 → `0.7 × 0.7 = 0.49` → Minion HP 500 → **245** (51% 감소)
- **주의:** 이 공식만 반올림이 아니라 **내림(floor)** 이다. 다른 공식과 다르므로 구현 시 혼동 주의.

### 9-11. 선택지 등장 가중치

```
W_기본 = max(0, w + w_slot × max(0, 빈자리수))     // w=1, w_slot=영입만 4
W_최종 = W_기본 + P_투자 × w_point                 // w_point = 1
```

- **예시:** 파티 1명(빈자리 3), 영입 투자 0 → 영입 `1 + 4×3 = 13`, 나머지 8종 각 1 → 영입 **13/21**
- **주의:** 포인트 1점이 가중치 +1이라, 기본 가중치가 1인 현재 값에서 1점의 영향이 2배로 매우 크다.

### 9-12. 가중치 비례 · 중복 없는 추첨

```
P(i) = max(0, w_i) / Σ(k ∈ 남은 후보) max(0, w_k)
→ 1개 뽑을 때마다 후보에서 제거 후 재정규화
```

- **예시:** 가중치 `[13, 1, 1, 1]`에서 2개 추첨 → 1차 합 16, 첫 항목 81% → 뽑히면 남은 `[1,1,1]`이 각 1/3로 재정규화
- **적용처:** 선택지 3종 추첨, 영입 후보 3종 추첨

### 9-13. 몬스터 대상 선택 (어그로 가중치)

```
P(i) = max(0, w_i) / Σ(k ∈ 생존) max(0, w_k)
```

- **예시:** Knight(4) / Barbarian(3) / Mage(1) / Ranger(1), 합 9 → **44% / 33% / 11% / 11%**
  Knight 사망 시 합이 5로 줄어 Barbarian 60% / 후열 각 20%로 자동 재정규화
- **상한/하한:** 후열도 최소 1 이상을 유지할 것(0이면 사실상 표적이 되지 않아 전투가 단조로워진다)
- **주의:** 광역기(Scope = Line)는 이 공식을 타지 않는다.

### 9-14. 턴 순서 정렬

```
1순위: 유효 SPD 내림차순
2순위: 고유 ID 오름차순 (안정적 타이브레이커)
```

- **예시:** Rogue_Dagger(150) / Knight(100) / Skeleton_Minion(70) → Rogue → Knight → Minion
- **주의:** 아군과 적이 동속일 때 고유 ID 오름차순 규칙 탓에 항상 적군이 먼저 행동할 수 있다. (→ 12항 위험 R-03 참조)

### 9-15. 영구 포인트 획득 / 잔여

```
획득 = floor(BestStage / stagesPerPoint)       // stagesPerPoint = 10
잔여 = 획득 - Σ투자
```

- **예시:** BestStage 37, 공격력에 1점 투자 → 획득 `floor(37/10) = 3` → 잔여 **2 / 총 3**
- **밸런스 의도:** 획득량을 별도 저장하지 않고 최고 기록에서 파생시켜 값이 어긋날 여지를 없앴다. 리스펙은 무료다.
