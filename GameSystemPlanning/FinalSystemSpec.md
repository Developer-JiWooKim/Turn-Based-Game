# 최종 시스템 기획서 — Endless Expedition

## 1. 시스템 이름

**전투 & 로그라이크 보상 시스템 (Battle & Roguelike Reward System)**

---

## 2. 시스템 목적

> 본 시스템은 `'전투 중 타겟팅 판단'`과 `'클리어 후 보상 선택'`이라는 두 가지 핵심 의사결정을 통해 파티를 성장시키고, 지수적으로 강해지는 적들에 맞서 **최대한 많은 스테이지 돌파하는 것**을 목적으로 한다.

- **전략적인 턴제 전투 (타겟팅 판단)**
  - 복잡한 조작 대신, 적의 행동 순서·위협도·아군 스킬(도발, CC기 등)을 고려한 `우선 타겟팅`에 집중하여 전투 피해를 최소화 하도록 유도한다.

- **성장 구조의 단순화 (성장 체계)**
  - 장비·아이템·EXP 등 불필요한 성장 변수를 제거하고, `스테이지 클리어 보상 선택(영입/스탯/디버프 등)`과 `파티 조합 시너지`요소로만 파티를 성장시켜 플레이어의 판단 밀도를 높인다.

- **특화 빌드 구축 유도 (난이도 설계)**
  - 스테이지가 진행됨에 따라 몬스터의 능력치는 `지수적으로 증가`한다.
  - 시스템이 제공하는 기본 성장(선형 성장)만으로는 난이도 상승을 따라갈 수 없으므로, 플레이어가 `자신만의 특화 빌드`를 탐색하고 구축하도록 강한 동기를 부여한다.

## 3. 핵심 규칙 요약

| 번호 | 규칙 |
| :--- | :--- |
| 1 | 행동 가능한 모든 유닛은 1턴에 정확히 1회 행동한다.|
| 2 | 턴 순서는 매 턴 재정렬한다. (1순위: 유효 SPD 내림차순, 2순위: 고유 ID 오름차순) |
| 3 | 파티원은 최대 4명이며, 4명 상태에서 추가 영입 시 기존 파티원 1명을 반드시 대체해야 한다. |
| 4 | 사망한 아군은 파티에서 영구 제거되며, 시너지 조건 미달 시 시너지는 즉시 해제된다. |
| 5 | 5의 배수 스테이지는 보스 웨이브이며, 클리어 시 보상 선택 **이전** 시점에 진행 상황을 자동 저장한다. |
| 6 | 파티 전멸 시 세이브 데이터를 영구 삭제하고 최고 기록을 갱신한다. |
| 7 | 스테이지 클리어 시 9종 선택지 중 가중치 추첨으로 중복 없이 3종을 제시하며, 플레이어는 1종을 필수 선택한다. |
| 8 | 전투 중 발생한 모든 상태이상(버프/디버프)은 **스테이지 클리어 시 일괄 해제**된다. |

## 4. 입력 정보

### 런타임 입력 (직전 시스템(Save Data)/이전 스테이지에서 인계)

| 입력명 | 자료형 | 설명 |
| :--- | :--- | :--- |
| `Stage_Index` | int | 현재 스테이지 번호 (1 이상) |
| `Party_Data` | list | 파티원 목록(최대 4), 각 유닛의 현재 HP / 누적 선택지 성장분 / 시너지 |
| `Choice_Weight` | dict | 선택지 카테고리별 투자 포인트 (Run Setup에서 배분) |
| `Pending_Enemy_Debuff` | float×2 | 이전 스테이지 선택지로 예약된 몬스터 HP/ATK 배율 |
| `Best_Stage` | int | 저장된 최고 스테이지 기록 (영구 포인트 산출용) |

### 플레이어 입력

| 단계 | 입력 | 대응 조작(Default) |
| :--- | :--- | :--- |
| 전투 | 타겟 지정 | 마우스 클릭 / 키보드 방향키(좌·우) |
| 전투 | 공격·스킬 확정 | 마우스 클릭 / Space / Enter |
| 보상 | 선택지 선택·확정 | 마우스 클릭 / 키보드 방향키(좌·우) |

- **키 바인딩 옵션**: 플레이어 조작 입력의 모든 키 매핑은 설정(Option) 메뉴를 통해 플레이어가 임의로 재지정할 수 있다.

## 6. 기본 흐름

```
1) [조우 진입]   Stage_Index로 웨이브 구성 판정 → 몬스터 스폰
                 (기준 스탯 → 스테이지 스케일링 → 예약 디버프 배율 순으로 적용)
2) [턴 정렬]     생존 전원의 유효 SPD 비교 → 행동 큐(Queue) 생성
3) [턴 수행]     Queue 순서대로 1유닛씩 행동
                   3-1) 턴 시작 처리: 도트 피해 → 지속 턴 감소 → 기절 판정(기절 시 행동 스킵)
                   3-2) Player Turn: 타겟팅 입력 → 공격/스킬 확정 → 데미지 연산 → 연출
                        Enemy Turn : 어그로 가중치 추첨으로 타겟 선정 → 동일 연산
                   3-3) 사망 판정 (HP 0 도달 시 즉시 제거 / 아군 전멸 시 [전멸 처리] 이동)
4) [턴 순환]     Queue 전원 행동 완료 → 턴 종료 → 2)로 복귀(SPD 재정렬)
5) [조우 클리어] 적 전멸 → 상태이상 전부 해제
                   5-1) 보스 스테이지였다면 자동 저장
                   5-2) 선택지 가중치 산출 → 중복 없는 3종 추첨 → UI 출력
                   5-3) 플레이어 선택 1종 반영
6) [다음 진행]   Stage_Index += 1 → 플레이어 자동 성장 차분 적용 → 1)로 복귀

※ [전멸 처리] 아군 전멸 발생 시 → 세이브 데이터 삭제 → Final Result 화면 출력 (종료)
```

## 7. 조건 분기

| 조건 | 처리 |
| :--- | :--- |
| `stage ≤ 5` | 수동 설계 웨이브 구성을 그대로 사용(Tutorial Wave) |
| `stage > 5` 이고 `stage % 5 ≠ 0` | 일반 몬스터 풀에서 가중치 추첨 |
| `stage % 5 == 0` | 보스 풀에서 추첨(보스급 몬스터 반드시 포함), 보스 BGM 재생 |
| 보스 스테이지 클리어 | 선택지 제시 **전** 자동 저장(Party_Data / Stage_Index / Choice_Weight / Pending_Enemy_Debuff), 저장 알림 표시 |
| 보스 스테이지 클리어 (SPD 스케일링) | 플레이어 SPD 보상 차분 적용 (+기준 SPD의 8%), 다음 스테이지 몬스터 SPD 12% 복리 증가 |
| 선택지 == 영입, 파티 인원 == 4 | 교체 대상 선택 UI 출력 → 대체 확정 |
| 선택지 == 적 디버프 | **선택한 디버프 다음 스테이지 1회** 예약, 배율은 곱연산 누적 |
| 선택지 == 적 행동불가(EnemyStun) | 배율이 아닌 기절 1턴 확정 부여로 처리 |
| 스킬 Scope == Line(광역) | 어그로 가중치 추첨을 타지 않고 후보 전원이 대상 |

## 8. 예외 상황

| 상황 | 처리 |
| :--- | :--- |
| 아군 1인 HP 0 도달 | 파티에서 즉시 영구 제거. 시너지 조건 미달 시 시너지 즉시 해제. 남은 인원으로 전투 계속 |
| 아군 전원 사망 (Game Over) | 전투 즉시 종료 → 결과 화면 → 세이브 영구 삭제 → 최고 기록 갱신 → Meta_Point 지급 → 타이틀 복귀 |
| 도트 피해로 사망 | 행동 실행 **전**에 사망 처리. 해당 유닛은 그 차례에 행동하지 못함 |
| 플레이어 턴 중 [배틀 중단] 클릭 | 확인 팝업(`"현재 진행은 저장되지 않으며, 마지막 저장 지점부터 시작합니다."`) → 확인 시 마지막 Auto-Save 유지 상태로 타이틀 복귀 |
| 유닛 행동 중 Pause 진입 | Pause UI는 열리되 [배틀 중단] 버튼은 Disabled 처리 |
| 동일 상태이상 재부여 | 지속 턴·Magnitude 각각 **더 큰 값**으로 갱신. 약한 재부여가 강한 상태를 덮어쓰지 않음 |
| 선택지 가중치 총합 ≤ 0 | 균등 추첨으로 대체 (아무것도 뜨지 않는 상황 방지) |
| 어그로 가중치 총합 ≤ 0 | 균등 추첨으로 대체 |

## 9. 사용 공식

전체 15종. 상세 유도와 밸런스 의도는 `SystemFormulaBalance.md` 참조.

| 번호 | 공식명 | 수식 (Formula / Algorithm) | 비고 / 제약 |
| :---: | :--- | :--- | :--- |
| **9-1** | 데미지 계산 | `감쇠 = K / (K + DEF_eff)`<br>`기본피해 = ATK_eff × 감쇠 × m`<br>`최종피해 = rng < CritRate ? 기본피해 × CritDmg : 기본피해`<br>`피해량 = max(1, round(최종피해))` | $K = 1000$<br>$m$: 스킬 배율 (일반공격: 1.0)<br>최소 피해량: 1 |
| **9-2** | 몬스터 스케일링 | `steps = max(0, stage - 1)`<br>`normalSteps = min(steps, 29)` (accelStart = 30)<br>`accelSteps = steps - normalSteps`<br>`배율 = (1+rate)^normalSteps × (1 + rate×2.0)^accelSteps`<br>`스탯 = max(1, round(기준값 × 배율))`<br>`spdSteps = floor(max(0, stage - 1) / 5)`<br>`SPD = max(1, round(SPD_base × (1.12)^spdSteps))` | $accelMul = 2.0$<br>SPD는 보스 처치(5stage 단위) 시에만 12% 복리 증가 |
| **9-3** | 플레이어 자동 성장 | `G(step) = round(base × rate × step)`<br>`ΔG(step) = G(step) - G(step-1)`<br>`B(step) = floor(step / 5)`<br>`ΔSPD(step) = G_spd(B(step)) - G_spd(B(step-1))` | SPD는 보스 처치(5stage 단위) 시에만 상승 |
| **9-4** | 영입자 소급 성장 | `Stats_합류 = base + G(stage - 1)` | 영입 시 전 단계 성장분 소급 적용 |
| **9-5** | 선택지 스탯 성장 | `기준스탯 = Stats - ChoiceGrowth`<br>`Stat += round(기준스탯 × rate)` (HP/ATK/SPD/DEF)<br>`Stat = min(1, Stat + Δ)` (치명타율/저항)<br>`Stat += Δ` (치명타피해)<br>`HP += round(MaxHp_실제 × healRate)` (회복) | 기존 선택지 누적 성장분 제외 후 비례 적용<br>치명타율/저항: 100% Clamped |
| **9-6** | 파티 시너지 | `Stat += round(Stat × rate)` (ATK/SPD/DEF)<br>`Stat = min(1, Stat + Δ)` (치명타/저항)<br>`Stat += Δ` (치명타피해) | 혼합 모델 스탯 부여 |
| **9-7** | 상태이상 부여 | `P_성공 = ApplyChance × (1 - clamp(RES, 0, 1))` | 저항(RES) 반영 확률 연산 |
| **9-8** | 상태이상 스탯 감소 | `Stat_eff = max(0, round(Stat_base × (1 - min(1, Magnitude))))` | 디버프 스탯 차감 |
| **9-9** | 도트(중독) 피해 | `피해 = max(1, round(MaxHp × Magnitude))` | 최대 HP 비율 피해 (최소 1) |
| **9-10** | 예약 디버프 중첩 | `누적배율 *= 선택지배율`<br>`몬스터스탯 = max(1, floor(Stat × 누적배율))` (적용 후 누적배율 = 1) | 다음 스테이지 1회 예약 적용 |
| **9-11** | 선택지 등장 가중치 | `W_기본 = max(0, w + w_slot × max(0, 빈자리수))` ($w=1, w\_slot=4$ [영입만])<br>`W_최종 = W_기본 + P_투자 × 1` | 빈자리 보정 및 런타임 투자 가중치 반영 |
| **9-12** | 선택지 비복원 추첨 | `P(i) = max(0, w_i) / Σ max(0, w_k)` | 1개 추첨 후 후보 제거 & 재정규화 |
| **9-13** | 몬스터 어그로 추첨 | `P(i) = max(0, w_i) / Σ(생존자) max(0, w_k)` | 생존 파티원 대상 가중치 추첨 |
| **9-14** | 턴 순서 정렬 | 1순위: 유효 SPD 내림차순<br>2순위: 고유 ID 오름차순 | 매 턴 재정렬 (안정적 타이브레이커) |
| **9-15** | 영구 포인트 산출 | `획득 = floor(BestStage / 10)`<br>`잔여 = 획득 - Σ투자` | $stagesPerPoint = 10$ |
